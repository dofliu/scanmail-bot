# ScanMail+ Android App

同一份前端，一邊在電腦瀏覽器跑，一邊打包成手機 App。

---

## 為什麼是這個架構

ScanMail+ 的重活全在後端：OpenCV 邊界偵測、Gemini Vision 辨識、PDF/影片處理、SMTP 寄信。
這些是 Python，**跑不進手機裡**。所以 App 不是「把整個系統搬到手機」，
而是「把既有的前端裝進手機，後端仍然在電腦或伺服器上」。

```
                    static/  ← 唯一的前端來源，開發功能只改這裡
                       │
          ┌────────────┴─────────────┐
          ▼                          ▼
   桌面瀏覽器                    Android App
   FastAPI 直接送出          build_mobile.py 打包進 APK
   http://localhost:8000       （React/pdf.js/字型都內建）
          │                          │
          └────────────┬─────────────┘
                       ▼
              同一個 FastAPI 後端
        （掃描 / AI / 寄信 / 檔案處理都在這裡）
```

外殼用 [Capacitor](https://capacitorjs.com/)：Android 專案是一個載入本機網頁的 WebView，
再加上 App 才有的能力（存檔、分享、狀態列、啟動畫面）。

---

## 前置需求

| 工具 | 版本 | 用途 |
|------|------|------|
| Node.js | 18 以上（建議 20 / 22） | Capacitor CLI、esbuild |
| JDK | 21 | Gradle 建置 |
| Android SDK | compileSdk 36、build-tools 36 | 產生 APK（裝 Android Studio 最省事） |
| Python | 3.10 以上 | `scripts/build_mobile.py` |

第一次要先裝 Node 相依套件（之後 `build_mobile.py` 會自動檢查）：

```bash
cd mobile && npm install
```

## 情境 A：在電腦上開發（跟以前完全一樣）

```bash
uvicorn main:app --reload
# 開 http://localhost:8000
```

改 `static/` 底下任何檔案，重整瀏覽器就看得到。**這條路徑沒有任何改變。**

---

## 情境 B：改一次，電腦和手機同時看

App 直接載入電腦上的 dev server，所以手機看到的就是最新的前端，改完存檔重整就好，
不必重新打包 APK。

```bash
# 1. 後端對區網開放（--host 0.0.0.0 是關鍵，預設只聽 127.0.0.1）
uvicorn main:app --reload --host 0.0.0.0 --port 8000

# 2. 查電腦在區網的 IP
#    macOS/Linux: ip addr | grep 192.168      Windows: ipconfig

# 3. 讓 App 指到那台電腦
python scripts/build_mobile.py --dev-server http://192.168.1.50:8000 --sync

# 4. 裝到用 USB 連著的手機
cd mobile/android && ./gradlew installDebug
```

之後改 `static/` → 存檔 → 手機上把 App 關掉重開（或下拉重整）就是新版本。
電腦瀏覽器同時開著同一個位址，兩邊看到的是同一份程式碼。

> **注意**：這個模式下 APK 被綁在那個 IP 上，換網路就連不到。
> 要回到一般模式，重跑一次不帶 `--dev-server` 的建置即可。
>
> 另外，live-reload 模式載入的是 `static/` 原檔，沒有 Capacitor 橋接層，
> 因此「下載處理結果」會走瀏覽器的路徑而在 WebView 裡無效。
> 要驗證下載功能請用情境 C 的打包版本。

## 情境 C：打包可以發出去的 APK

```bash
# 後端位址直接打包進去（校內伺服器或固定 IP 的電腦）
python scripts/build_mobile.py --api-base https://scanmail.example.com --sync

cd mobile/android
./gradlew assembleDebug      # 測試用
./gradlew assembleRelease    # 發佈用
```

APK 產出位置：

```
mobile/android/app/build/outputs/apk/debug/app-debug.apk
mobile/android/app/build/outputs/apk/release/app-release.apk
```

不指定 `--api-base` 也可以 —— App 第一次開啟會出現設定畫面，
請使用者自己輸入伺服器位址並測試連線，之後記在手機上。
一個 APK 就能給不同人連不同伺服器。

隨時可以在 App 內的 **設定 → 伺服器連線** 換位址。

**位址從 v3.21.0 起存在 Capacitor Preferences**（原生 SharedPreferences），
跟簽名庫同一層（`SMNative.store`）。在那之前它存在 `localStorage`，
而 WebView 的 `localStorage` 會跟著 Android 的「清除快取」一起被清掉 ——
使用者只是清了一次快取，App 就跳回設定畫面要人重打一次 IP。
現在清掉快取位址還在，升級後第一次開啟也會自動把舊位址搬過去。
細節（尤其是 `config.js` 排在 `native.js` 之前造成的載入順序問題）見
[ARCHITECTURE.md](ARCHITECTURE.md)。

## 情境 D：離線精簡版（不需要後端）

想要一個「隨手處理圖片」的工具，不想架伺服器、也不想在沒網路時卡住：

```bash
python scripts/build_mobile.py --offline --sync
cd mobile/android && ./gradlew assembleDebug
```

這個版本的 App **整個就是裝置端的媒體工具**：沒有掃描寄信、沒有導覽列、不用登入、
不會問伺服器位址。所有處理都在手機上直接做完，檔案不會離開裝置。

介面有四個分頁：**編輯**、**圖片**、**文件**、**頁面**。

### 🎨 編輯

**畫面上永遠只有畫布和一條工具列。** 所有選項都收在最下方，工具列依情境自動切換，
需要細調時才從下方推出面板，關掉就恢復滿版。

沒選圖時（拼貼模式）：

| 工具 | 內容 |
|------|------|
| ▦ 版面 | 直式 / 橫式 / 自動 / 2×2 / 2×3 / 3×2 / 3×3 / 4×4，點下去立刻套用 |
| ⬚ 圖框 | 無 / 圓角 / 細邊 / 白框 / 陰影 / 拍立得，另可調顏色、粗細、圓角 |
| ↔ 間距 | 格線間距、底色 |
| Ｔ 文字 | 疊字或平鋪浮水印：位置、字級、顏色、外框、濃度、角度 |
| ✍ 簽名 | 簽名庫：手寫、匯入圖片印章，然後拖到定位 |
| ＋ 加圖 · ✕ 清空 | |
| 💾 製作 | 輸出格式（JPG / PNG / WebP / **PDF**）與品質，然後儲存 / 分享（釘在右側不隨捲動） |

點畫布上任何一張圖（或下方縮圖）就切到圖片模式：

| 工具 | 內容 |
|------|------|
| ↺ ↻ | 左轉 / 右轉，按一下就看到 |
| ⇋ ⇅ | 水平 / 垂直翻轉 |
| ⇄ 交換 | 再點另一張，兩張的位置對調（多張時才出現） |
| ⊹ 重置取景 | 把格子內的縮放與位移還原 |
| ⌗ 拉正 | 自動抓出紙張四角，把斜拍的梯形拉回矩形 |
| ⛶ 裁切 | 進到獨立畫面自由拖框，也可鎖 1:1 / 4:3 / 3:4 / 16:9 / 9:16 |
| ▩ 打碼 | 拖框遮蔽，馬賽克 / 模糊 / 塗黑 |
| 🎚 調整 | 濾鏡預設、亮度 / 對比 / 飽和、大小 |
| 🗑 刪除 | |
| ✓ 完成 | 回到拼貼模式（釘在右側） |

正在編輯的那一張會在畫布上用虛線框標示。

選中之後畫布本身也吃手勢：

| 手勢 | 做什麼 |
|------|------|
| 單指拖曳 | 移動它在格子裡的位置（格狀版面會裁切填滿，拖曳決定露出哪一塊） |
| 兩指捏合 | 縮放，上限 6× |
| 點一下別張 | 改選那一張；在交換模式下則是跟它對調 |

**2×3 這類格狀預設用的是「裁切填滿」**：每一格大小完全一樣、圖片裁切後填滿格子，
這才是一般人講拼貼時期待的樣子。直式 / 橫式 / 自動則沿用等比縮放（留白露出底色），
與後端 `merge_images()` 的行為一致。

預覽用的是縮圖（長邊上限 1400px），所以按一下就有反應；
按下儲存時才用原圖重算一次，輸出品質不受預覽影響。
兩者共用同一套 `layoutBoxes()`，不會發生「預覽跟存出來的不一樣」。

### 已知的兩點差異（相對於後端版本）

* **輸出只支援 PNG / JPG / WebP。** Canvas 編不出 BMP / GIF（讀得進來，但存不出去）。
* **透明圖轉 JPG 會填白底**，後端則是直接丟掉 alpha（結果常常是黑底）。這裡刻意做得比較合理。

畫質方面，直接把大圖一次畫成小圖在瀏覽器裡是雙線性取樣，縮很多倍會糊；
引擎改成先反覆對半縮再畫最後一步，結果接近後端的 LANCZOS。

**批次結果不打包成 ZIP** —— 手機上還要再找程式解壓縮很麻煩。
改成列出每個檔案，可以單獨存，也可以「全部儲存」一次丟進系統分享面板
（App 內只會跳一次分享面板）。

#### 打碼

在要遮的地方拖一個框就好。畫面上直接顯示**遮完的樣子**而不是外框預覽 ——
遮得夠不夠一眼就知道，不用存檔出來才發現還看得到。已經遮好的框用虛線標著，
點一下可以拿掉。

| 樣式 | 做法 |
|------|------|
| 馬賽克 | 縮到很小再放大回來，關掉平滑才會是方格而不是糊成一片 |
| 模糊 | 連周邊一起取樣再模糊，裁回中心 —— 只取選區的話邊緣會透出半透明 |
| 塗黑 | 直接填色 |

三種都是**直接改像素**，不是蓋一層可以移除的東西。加上 Canvas 重新編碼本來就會
丟掉 EXIF，所以輸出的圖片也不含 GPS 座標與拍攝時間。

#### 調整

八組濾鏡預設 + 亮度 / 對比 / 飽和的細調。實作上是把值換成 CSS filter 字串交給
`ctx.filter`，走瀏覽器的 GPU 路徑，比自己逐像素算快得多，拉滑桿是即時的。

其中「**紙本**」（灰階 + 高對比 + 提亮）是給拍紙本文件用的 —— 泛黃的紙拉成乾淨的
黑白，比原樣拍出來好認很多，存成 JPG 也小很多。

#### 文字 / 浮水印

同一個面板，差在「平鋪」這個開關：關著是一段疊在圖上的文字（位置用九宮格挑，
手機上比拖曳準得多），打開就變成蓋滿整張、可調角度的浮水印。

字型直接用系統的 —— 畫在 canvas 上不必像 PDF 那樣把字型嵌進檔案，所以中文不用
額外成本。位置與字級都存成相對值（0–1、相對於短邊），縮圖預覽與原圖匯出才會長得一樣。

外框（描邊）預設是開的：白字壓在白紙上就是看不見，有一圈黑邊才到哪都讀得到。

#### 拼貼的取景與交換

格狀版面（2×2 這類）會把圖裁切填滿格子，原本一律取中央 —— 人臉在邊邊的照片就只能認了。
現在選了圖之後可以直接拖曳決定露出哪一塊、兩指捏合縮放。

取景存的是**相對值**（縮放倍率 + 0–1 的對焦點），所以在縮圖上調完，原圖匯出是一樣的構圖。
對焦點會夾在「實際可動」的範圍內 —— 不夾的話拖到底之後手指會累積一段拖了卻不動的空行程，
回拖時要先把那段還回來，感覺像卡住。

沒動過取景的圖走的還是原本那條繪製路徑，一個像素都不會變。

交換位置刻意要先按一下「⇄ 交換」再點目標，而不是直接「點 A 再點 B 就換」——
後者本來就是「改選 B」，做成直接交換的話就再也沒辦法用點的切換選取了。
畫布與下方縮圖列共用同一條選取邏輯，縮圖列在手機上點得準得多。

點選與拖曳共用同一塊畫布，靠 **4px 位移門檻**分辨；而且只有拖「已經選中的那張」才算移動
—— 不然點旁邊的圖會把它撞位。

#### 即時取景（對準了才拍）

空畫面的「📷 用相機拍一張」、或工具列的「📷 拍照」會開啟取景畫面：相機預覽上
**即時疊著文件的邊框**，抓到了框就變綠、抓不穩是黃色並列出該怎麼調整。
以前的順序是「先拍 → 進編輯器 → 按拉正 → 才知道歪不歪」，歪了就整套重來。

框穩住之後**會自己按下快門**（v3.22.0）：底下有一條穩定度長條與倒數，
按快門的手正是最容易把畫面碰歪的那隻手。不想要就按「⏱ 自動」關掉，
關掉之後這次開 App 都維持關著（偏好還沒存進原生儲存，關機會回到預設的「開」）。

四個實作上的取捨（引擎在 `static/js/scan-live.js`）：

* **偵測要節流**。偵測是同步的、會擋住 UI 執行緒，所以不是每幀都跑：一次跑完才排下一次，
  兩次之間至少隔 350ms，取樣也先縮到 640px 寬。沒有這條，慢一點的手機會一路排隊到畫面卡死。
* **框要平滑，但不能黏住**。手持一定會抖，逐幀的框會跳，所以用 EMA 收斂；
  但角點平均位移超過畫面的 10% 就直接跟上 —— 鏡頭是真的移開了，這時候慢慢跟過去更難看。
* **快門對留下來的那一張重測**。取景時的偵測結果是「上一張」的，手持之下兩張不會一樣。
  多花一次 100–300ms，換來拉正畫面看到的框**就是照片本身的框**，
  不會出現「拍完框就變了」。這個框會跟著照片進編輯器，按「⌗ 拉正」直接沿用。
* **穩定度量的是平滑前的角點**。平滑後的角點本來就會趨近不動，拿它算等於在量自己的
  濾波器。門檻是「連續 3 次角點平均位移 < 畫面的 1.2%」，而且**抓不準一律歸零** ——
  低信心的框本來就會飄，它「連續三次都在同一個地方」多半是連續三次都抓錯同一個東西。
  這兩個數字是估的（合成串流不會抖，調不出有意義的值），所以取景畫面把當下的位移
  百分比顯示出來：太少自動拍就放寬、拿著還在拍就收緊。

沒有後鏡頭的裝置（桌機、部分平板）會退回任何一顆鏡頭；權限被拒 / 沒有相機 / 被別的 App
佔用，都換成講得出下一步的訊息，而不是丟出瀏覽器的原始錯誤名稱。
離開取景畫面一定會關掉相機軌道 —— 漏收的話相機燈會一直亮著。

App 需要 `android.permission.CAMERA`（`AndroidManifest.xml` 早就宣告了，
Capacitor 的 WebView 會把網頁的權限請求轉成系統詢問）。離線版一樣能用，全程在裝置上跑。

#### 拉正（邊界偵測 + 透視校正）

拍桌上的紙，點「⌗ 拉正」就自動抓出四個角、把斜拍的梯形拉回矩形。抓得不對可以自己拖，
抓不到就明講「⚠ 沒把握」請你確認 —— **亂裁一通比不裁更糟，使用者不會發現。**

沒把握的時候，警告下方會列出**該怎麼重拍**：紙面反光、光線不足、文件在畫面裡太小、
紙跟桌面顏色太接近、四個角沒全部入鏡。這些量測值在偵測時本來就算過了
（亮度積分圖、梯度圖、四邊形面積），只是以前沒換算成使用者的下一個動作 ——
單講一句「沒把握」的結果就是原地再拍一張一模一樣的照片。

這一塊本來只長在後端的 OpenCV 裡。搬進裝置時沒有照抄：

| | 後端 v5 | 裝置端 |
|------|------|------|
| 偵測策略 | 七種並行再評分挑最好的 | 只留梯度導向的 Hough 直線偵測 |
| 為什麼 | 有 Python + OpenCV 的預算 | 文件的邊本來就是直線；直線由整條邊投票決定，**角被手指擋住也不影響** |
| 評分 | 凸性 + 逐邊梯度支持度 + 最弱邊門控 | 同左（整套照搬，那是 22 個案例的基準測試磨出來的） |
| 角點精度 | 中位數 0.6px（有次像素精修） | 約 2–6px（在 480px 工作解析度上抓完放大回原圖） |

校正走 **WebGL** —— canvas 2D 只做得到仿射，做不到投影變換。一支 fragment shader
逐像素反推來源座標；拿不到 WebGL 的裝置退回「切成細格、每格用仿射近似」。

輸出尺寸用 **Zhang–He 法從透視幾何反推真實寬高比**，不然斜拍的 A4 拉正後會被拉扁
（影像上量到的寬高比跟 1:√2 差很多）。

拉正是**破壞性**的（換掉原圖、清掉已經沒有意義的裁切框），所以畫面裡留了「⟲ 還原原圖」。

#### 簽名 / 印章

這個平台的用途是寄公文、合約、收據，而這些文件常常就差一個簽名。原本得
「印出來 → 簽 → 再掃一次」，現在手指簽一次存起來，之後拖到定位就好。
編輯分頁與頁面分頁共用同一個簽名庫。**App 內存在 Capacitor Preferences**
（原生 SharedPreferences）而不是 `localStorage` —— WebView 的 `localStorage` 會跟著
Android 的「清除快取」一起被清掉，簽名庫放那裡等於隨時可能不見。網頁版沒有這個外掛，
照舊用 `localStorage`；升級到 v3.17.0 之後第一次開啟，舊簽名會自動搬過去。
這層的入口是 `SMNative.store`（`static/js/native.js`），詳見
[ARCHITECTURE.md](ARCHITECTURE.md)。

**手寫簽名存的是筆畫的點而不是像素**，所以蓋進 PDF 時輸出的是向量路徑 ——
放大不糊、列印跟原生文件一樣銳利，一枚只佔幾 KB。曲線用「相鄰兩點的中點連成二次貝茲」；
PDF 沒有二次貝茲運算子，換算成三次，兩邊算的是同一條線，所以畫面上看到的就是蓋出來的。

**匯入圖片當印章**：拍一張紙上的簽名或關防，用亮度當透明度去掉白底。

| 模式 | 用途 |
|------|------|
| 保留原色 | 紅色關防 —— 紅留著，白底去掉 |
| 轉成墨色 | 太淡的鉛筆 / 原子筆，整個換成選定的墨色 |

蓋進 PDF 走影像 XObject + **SMask 軟遮罩**，中間是真的透明；印章是不規則形狀，
沒有這一層的話白底會把底下的字整個蓋掉。

> ⚠️ 這是「蓋一張圖上去」，**不是 PKI 意義上的數位簽章**，不具法律效力。

#### 自由裁切

固定比例的置中裁切不夠用 —— 拍紙本文件時要裁掉的是桌面，位置每次都不一樣。
點「裁切」會進到獨立畫面：四角可拖、框內可移、有三分線輔助，比例列可以鎖成
自由 / 1:1 / 4:3 / 3:4 / 16:9 / 9:16。

實作上有兩個地方值得記著：

* **裁切排在旋轉之後**（`renderItem` 先轉再裁）。使用者拉的框是他在畫面上看到的，
  倒過來做會裁到別的地方。`cropRect` 存的是「轉正之後」的相對座標（0–1）。
* **轉圖 / 翻圖時裁切框跟著轉**（`rotateRect` / `flipRect`）。不然按一下旋轉，
  已經裁好的範圍就會飄到別處。

### 🔄 圖片

縮放、壓縮、轉檔是同一件事，所以併成一次處理：選好檔案，一起設定長邊上限、
輸出格式與品質，只重新編碼一遍。

也可以選「📕 合併成 PDF」，把多張照片變成一份多頁 PDF —— 紙張可挑
貼合圖片 / A4 / A5 / Letter。

#### 照片轉 PDF 為什麼不掉畫質

PDF 的 `/DCTDecode` 濾鏡吃的就是 JPEG 原始位元組，所以手機拍的照片是
**原樣**放進 PDF：不解碼、不重新編碼、檔案大小跟原檔一樣。只有這幾種情況才重壓一次：

| 情況 | 為什麼 |
|------|------|
| 漸進式 JPEG（SOF2）、算術編碼 | PDF 檢視器常常畫不出來 |
| CMYK（4 通道） | 還要處理 Adobe 的反相標記，不值得 |
| PNG / WebP | 不是 JPEG |
| 有設長邊上限而且圖太大 | 縮小一定要重新編碼 |

轉完會告訴你幾張是原樣嵌入的。

Exif 方向另外處理：PDF 檢視器不看 Exif，所以直式照片原樣放進去會躺著。
解法是把方向換算成 PDF 的變換矩陣（`ORIENT` 表，八個方向都有），
照片本身仍然原封不動。

### 📑 文件

PDF / Word / Markdown 的互轉，一樣完全在裝置上做完。

| 讀得進來 | 產得出去 |
|------|------|
| PDF、Word（.docx）、Markdown、純文字 | PDF、Word、Markdown、純文字、HTML |

中間隔一層共用的文件模型，所以是任意組合而不是寫死的每一對轉換。標題階層、
項目符號、編號清單、表格、引用、程式碼區塊、粗體斜體、超連結都會保留。

選好檔案會先顯示解析後的排版預覽 —— 轉檔前就看得出來有沒有讀歪，
比事後開檔案才發現好。工具列同樣是情境式的：格式 / 頁面（只有輸出 PDF 時出現）/
換檔 / 清空，右側釘著「轉換」。

#### PDF 輸出為什麼要打包字型

PDF 規格要求字型必須嵌在檔案裡，收到檔案的人才看得到中文 —— 沒有「用系統字型」
這個選項，而且 WebView 也拿不到 Android 內建字型的檔案。

所以 App 內建一份裁過的 **Noto Sans TC**（`static/vendor/fonts/`，OFL 授權）：

| | |
|------|------|
| 涵蓋範圍 | Big5 全字集（常用 + 次常用漢字）、ASCII、注音、假名、標點與常用符號 |
| 大小 | 4.6 MB（原始 7.1 MB / 20812 字符） |
| 產生方式 | `python scripts/make_pdf_font.py`（需要 fonttools） |

輸出時 `static/js/ttf-lite.js` 會**再裁一次**，只把這份文件實際用到的字寫進 PDF。
一份幾百字的文件通常只有 30–80 KB，不會背著整份字型。同時附上 ToUnicode 對照表，
所以 PDF 裡的中文可以複製、可以搜尋，不是一張圖。

文件裡若出現字型沒有的字（例如罕見異體字），轉檔後會跳出提示列出是哪幾個字，
而不是安靜地留一片空白。

### PDF → 圖片

文件頁選 PDF 進來時，輸出格式會多一個「🖼️ 圖片」：每頁算成一張圖，
可挑 100（省空間）/ 150（一般）/ 300 dpi（列印）。

走的是 pdf.js 的完整繪製，不是只抽文字，所以掃描件、表格、圖表都會原樣保留。
PDF 的頁面本身沒有背景色，繪製前會先鋪白底，不然存成 JPG 會變黑的。

#### PDF 讀取的限制

PDF 裡沒有「段落」這種結構，只有一堆帶座標的文字片段。還原方式是看字級
（比內文大就是標題）、行距（跳太多就是新段落）與行首符號（項目符號 / 編號）。
排版複雜的檔案（多欄、圖文混排）還原出來的結構會比較粗糙。

**掃描出來的圖片型 PDF 抽不到文字**，這種情況會明確告訴你需要 OCR，
而不是給一份空白檔案。完整版可以走後端的 Vision 辨識。

### 📚 頁面

PDF 的合併、刪頁、抽頁、重排、轉向。

丟幾份 PDF 進去，所有頁面併成一張縮圖總表（多份檔案會標 A / B / C）。工具列一樣是
情境式的：沒選頁時是加檔 / 清空 / 輸出，點某一頁就換成左轉 / 右轉 / **簽名** / 前移 /
後移 / 刪除。蓋過章的頁面在總表上標 ✍，三十頁的文件也找得到簽在哪。

重排刻意用「前移 / 後移」而不是拖曳 —— 手機上拖曳排序很難拖準，尤其是要跨行移動時。

#### 簽名蓋在哪裡就是哪裡

這件事比看起來麻煩：PDF 的 `/Rotate` 是**交給檢視器轉的**，內容串流裡的座標不會跟著轉。
使用者在轉過向的頁面上點右下角，直接寫進去很可能蓋到左上角。

所以蓋章的內容前面會先套一層「畫面座標 → PDF 座標」的變換矩陣，四個方向各一組：

| /Rotate | 矩陣 | 畫面左上角落在 |
|------|------|------|
| 0 | `1 0 0 -1 0 h` | PDF 左上 |
| 90 | `0 1 1 0 0 0` | PDF 原點 |
| 180 | `-1 0 0 1 w 0` | PDF 右下 |
| 270 | `0 -1 -1 0 w h` | PDF 右上 |

另外還有兩件不做就會出事的：原本的內容要包進 `q…Q` 再接簽名（它可能留下改過的座標系
或顏色），以及 `/Resources` 要複製一份再改（常被好幾頁共用，直接改會改到別頁）。

#### 無損是什麼意思

頁面連同它參照到的字型、圖片、色彩空間整包搬過去，**內容串流原封不動**：
不解碼、不重新編碼、不重畫成點陣圖。所以文字還是文字（複製得出來、搜尋得到），
圖還是原本那張圖，檔案大小也不會膨脹。

做法是自己寫了一層 PDF 物件解析器（`static/js/pdf-lite.js`）：

| 步驟 | 說明 |
|------|------|
| 讀 xref | 傳統表與 PDF 1.5 之後的 xref 串流都認；串流要先解 Flate 再還原 PNG 預測子 |
| 展開物件串流 | 現代 PDF 會把一堆小物件壓成一包（ObjStm），不展開就什麼都讀不到 |
| 走頁面樹 | 收集所有 `/Type /Page`，順便把父節點的屬性繼承下來 |
| 挑頁複製 | 從頁面字典往下遞迴，遇到參照就連目標一起複製，重新編號 |
| 寫出 | 傳統 xref 表 —— 最保險，什麼閱讀器都讀得懂 |

真實世界的 PDF 常常有點壞，所以留了幾條退路：

* **xref 讀不動** → 退回整份掃描 `N G obj`，照樣找得到頁面
* **增量更新**（被註解過、簽過名的檔案）→ 沿著 `/Prev` 往回走，後面的覆蓋前面的
* **屬性寫在父節點上** → 抽頁時一起帶走，不然頁面尺寸會跑掉
* **加密的檔案** → 直接說「有加密保護，無法直接編輯頁面」，不給出壞掉的輸出

複製時有兩個地方刻意擋掉：`/Parent`（頁面樹由我們重建）與「指向沒被選到的頁面」的參照
（註解的跳頁目的地常常指向別頁，照抄會把整份文件一路帶過來）。

### 還沒有的東西

* **影片** — ffmpeg.wasm 本體就 25–30MB，在手機上壓一支影片要好幾分鐘且容易記憶體不足，
  評估後認為不適合放進 WebView App。
* **PDF 裡的圖片** — 轉成 Word / Markdown 時只抽文字，圖片不會保留；
  Markdown 的圖片語法轉出去時會變成「［圖片：說明］」的文字佔位。
  （想保留版面就用「PDF → 圖片」，整頁原樣繪製。）
* **PDF 書籤與表單** — 頁面操作不會保留目錄書籤與 AcroForm 欄位，跳頁的連結也會失效
  （指向別頁的參照會被拿掉，否則會把整份文件帶過來）。
* **等寬字型** — 程式碼區塊用的是同一份 Noto Sans TC（再帶一份等寬中文字型太大），
  有底色標示但字寬不對齊。
* **去背** — ONNX 模型加上執行環境要 +15MB，手機上一張還要跑好幾秒，評估後沒做。
* **一次只有一個文字圖層** — 沒辦法同時放一段說明文字又蓋浮水印。
* **OCR** — 掃描型 PDF 抽不到文字時只能明講需要 OCR。中文語言包大、辨識率也不如
  後端的 PaddleOCR，還沒做。
* **自動快門的門檻還沒在真機上量過** — 功能本身在 v3.22.0 已經做好（連續 3 次
  角點位移 < 1.2% 就自己拍），但那兩個數字是估的：合成串流完全不會抖，調不出有意義的值。
  取景畫面會顯示當下的位移百分比，拿真機手持看幾秒就知道要放寬還是收緊。
* **重拍建議說不出「照片糊掉」** — 反光 / 過暗 / 太遠 / 同色桌面 / 沒入鏡都判得出來，
  對焦沒對到判不出來：現有的梯度圖裡，一張清楚的空白紙跟一張糊掉的照片分數一樣。

> 完整版仍然保有全部功能，兩種版本共用同一份 `static/`，
> 差別只在打包時有沒有加 `--offline`。

## 從原始碼到手機上：完整流程

```
static/                     唯一的前端來源（改功能只改這裡）
   │
   │  python scripts/build_mobile.py [--offline] [--api-base URL] --sync
   │    ├─ 複製到 mobile/www/
   │    ├─ CDN 依賴換成內建檔案（React / pdf.js / 字型）
   │    ├─ esbuild 預編譯 .jsx → .js
   │    ├─ 注入 SM_NATIVE（與 --offline 時的 SM_OFFLINE）
   │    └─ 從 main.py 讀版本號寫進 version.properties
   ▼
mobile/www/                 產物，不進版控
   │
   │  npx cap sync android   （--sync 會自動做）
   ▼
mobile/android/             Capacitor 的 Android 專案（進版控）
   │
   │  ./gradlew assembleDebug   或   assembleRelease
   ▼
app-debug.apk / app-release.apk
```

版本號的唯一來源是 `main.py` 的 `version="x.y.z"`，改那裡就會一路同步下去。

### 拿到 APK 的三種方式

**A. 自己建（要有 JDK 21 + Android SDK）**

```bash
cd mobile && npm install          # 第一次
cd .. && python scripts/build_mobile.py --offline --sync
cd mobile/android && ./gradlew assembleDebug
# → mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

**B. 從 CI 的 Artifacts 抓**（不必裝任何建置工具）

每次 push 到任何分支，`.github/workflows/android.yml` 都會建置兩份 debug APK 並上傳：

| Artifact | 內容 |
|------|------|
| `scanmail-offline-apk` | 離線精簡版（不需要後端） |
| `scanmail-debug-apk` | 完整版（需要後端） |

到該次 workflow run 的頁面下載即可。⚠️ 兩個限制：**要登入 GitHub**，而且下載的是
**`.zip` 不是 `.apk`**（Actions artifact 一律打包成 zip），Android 不能直接裝 zip 裡的檔案，
得先解壓縮。Artifact 預設保留 90 天。

**C. 用 nightly.link 拿免登入連結**（repo 是公開的才能用）

```
https://nightly.link/dofliu/scanmail-bot/workflows/android/main/scanmail-offline-apk.zip
```

這個網址永遠指向 `main` 最新一次成功建置，適合當書籤。一樣是 zip，一樣要解壓縮。

**D. 打 `android-v*` 標籤，從 GitHub Release 直接下載 `.apk`（推薦）**

```
https://github.com/dofliu/scanmail-bot/releases
```

打 tag 時 workflow 會建立一個 GitHub Release，附上兩個檔案：

| 檔名 | 內容 |
|------|------|
| `scanmail-<tag>-full.apk` | 完整版（需要後端） |
| `scanmail-<tag>-offline.apk` | 離線精簡版（裝置端媒體工具） |

Release asset 是直接下載，**免登入、手機點連結就進安裝畫面**，不必解壓縮。

安裝時 Android 會因為不是 Google Play 簽章而跳「不明來源」警告，允許即可
（有設定 `ANDROID_KEYSTORE_BASE64` 等 secrets 的話是自己的 release 簽章；
沒設的話是未簽章 APK，同樣會跳警告）。

## `build_mobile.py` 做了什麼

| 步驟 | 說明 |
|------|------|
| 複製 | `static/` → `mobile/www/`（`mobile/www/` 是產物，不進版控）；缺少 PDF 內嵌字型會直接中止 |
| 換掉 CDN | React / pdf.js / 字型改成打包在 App 內的檔案，手機沒網路也開得起來 |
| 預編譯 JSX | 用 esbuild 先把 `.jsx` 轉成 `.js`，App 內不必再載 3MB 的 Babel 即時編譯 |
| 橋接 | 打包 `mobile/src/bridge.js` → `window.SMCap`（存檔、分享、狀態列） |
| 注入旗標 | `window.SM_NATIVE = true`，讓前端知道要用絕對位址呼叫 API；加 `--offline` 時另外注入 `window.SM_OFFLINE = true` |
| 版本 | 從 `main.py` 讀版本號寫進 `mobile/android/version.properties` |

中文字型沿用 Android 內建的 Noto Sans CJK，不另外打包（省好幾 MB，外觀幾乎沒差）。

## 後端要注意的設定

**1. 監聽位址**

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

預設的 `127.0.0.1` 只有電腦自己連得到，手機會連線逾時。

**2. CORS**

App 的 WebView 來源是 `https://localhost`，跟後端不同源。
`.env` 預設 `ALLOWED_ORIGINS=*` 可以直接用；如果要收斂，記得把 App 的來源加進去：

```env
ALLOWED_ORIGINS=https://localhost,https://scanmail.example.com
```

**3. 防火牆**

Windows 第一次啟動 uvicorn 時要允許 8000 埠的私人網路連線。

**4. 多裝置使用請開啟認證**

`ENABLE_AUTH=False`（預設）時，所有連進來的裝置共用同一個 `default_user`，
連掃描中的暫存影像也是共用的 —— 電腦和手機**同時**掃描會互相蓋掉。
一個人單獨使用沒問題；多人或多裝置請開啟認證，各自登入後就有獨立的資料與工作階段：

```env
ENABLE_AUTH=True
ENCRYPTION_KEY=<自己產生的獨立金鑰>
```

### 產生金鑰（只做一次，檔案請自行備份，弄丟就無法更新已上架的 App）

```bash
keytool -genkey -v -keystore scanmail-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias scanmail
```

```bash
export ANDROID_KEYSTORE_FILE=/絕對路徑/scanmail-release.jks
export ANDROID_KEYSTORE_PASSWORD=...
export ANDROID_KEY_ALIAS=scanmail
export ANDROID_KEY_PASSWORD=...

cd mobile/android && ./gradlew assembleRelease
```

沒設這些環境變數時仍然可以建置，只是產出未簽章的 APK（自己測試夠用）。

### 版本號

版本號的唯一來源是 `main.py` 的 `version="x.y.z"`：

* `versionName` = `3.15.0`
* `versionCode` = `31500`（`major*10000 + minor*100 + patch`）

改版時只要改 `main.py`，重跑 `build_mobile.py` 就會同步。
上架 Google Play 需要 `versionCode` 嚴格遞增，必要時可用 `ANDROID_VERSION_CODE` 覆寫。

## CI 自動建置

`.github/workflows/android.yml`：

* push / PR 動到 `static/`、`mobile/`、`scripts/build_mobile.py` → 先跑裝置端引擎的
  瀏覽器測試，再建置兩份 debug APK（完整版 `scanmail-debug-apk`、
  離線精簡版 `scanmail-offline-apk`），都放在該次 workflow 的 **Artifacts**

  | CI 測試步驟 | 驗什麼 |
  |------|------|
  | `test:image` | 圖片引擎：縮放 / 轉檔 / 拼接 / 打碼 / 文字 / 格子取景 |
  | `test:doc` | 文件轉檔：產完再讀回來比對 |
  | `test:pages` | PDF 頁面操作：pdf.js 讀回來 + qpdf 驗結構 |
  | `test:sign` | 簽名蓋章：把頁面畫出來數墨點，確認落在該落的位置 |
  | `test:scan` | 邊界偵測：合成有標準答案的影像，量角點誤差 |
  | `test:live` | 即時取景：用 `canvas.captureStream()` 當假相機走完整條路 |
  | `test:studio` | 離線版介面：情境工具列、手勢、各分頁流程 |

* 打 `android-v*` 標籤 → 另外分別建置完整版與離線版的 release APK，
  並建立一個 **GitHub Release** 把兩份 `.apk` 附上去（免登入、點下去就能裝，
  見上面「拿到 APK 的三種方式」的 D 項）。用 runner 內建的 `gh` CLI 建立 /
  更新，重複打同一個 tag 會用 `--clobber` 蓋掉舊檔而不是失敗
* 設定以下 repository secrets 後，release APK 會自動簽章：
  `ANDROID_KEYSTORE_BASE64`（`base64 -w0 scanmail-release.jks`）、
  `ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`
* 也可以手動觸發（workflow_dispatch）並指定要打包的後端位址

## 目前的限制

* **完整版的後端必須連得到。** 手機上沒有 Python，離線只能開得起 App，做不了事。
  只需要圖片與文件工具的話請改用情境 D 的離線精簡版。
* **iOS 沒有做。** Capacitor 支援 iOS，但需要 Mac + Xcode，且要另外 `npx cap add ios`。
* **App 內的「下載」是寫檔 + 叫出系統分享面板**，因為 Android WebView 不支援
  `blob:` 下載。可以存到「檔案」、雲端硬碟，或直接傳給別人。
* **`static/js/` 下的 `scanmail.js`、`app.js`、`image-tools.js` 等舊模組沒有被
  `index.html` 載入**（v4 的 React 介面已取代它們），也沒有跟著調整成 App 相容，
  未來若要重新啟用需一併處理 API 位址與下載行為。

## 疑難排解

| 症狀 | 可能原因 |
|------|----------|
| App 一開就出現「連線到伺服器」而且怎麼填都失敗 | 後端沒加 `--host 0.0.0.0`；手機和電腦不同網路；防火牆擋住 8000 |
| 畫面出得來但功能都轉圈圈 | 後端沒開，或 `ALLOWED_ORIGINS` 沒包含 `https://localhost` |
| 相機打不開 | 系統設定裡沒給 App 相機權限 |
| 背景任務（批次處理）卡在進度條 | 開了 `ENABLE_AUTH` 但 token 過期，重新登入 |
| `./gradlew` 找不到 SDK | 建立 `mobile/android/local.properties`，寫入 `sdk.dir=/你的/Android/sdk` |
| 剛 clone 下來直接跑 `./gradlew` 就失敗 | `capacitor-cordova-android-plugins/` 和 `www/` 是產物不進版控。先 `cd mobile && npm install`，再 `python scripts/build_mobile.py --sync` |
| 改了 `static/` 但 App 沒變 | 忘了重跑 `python scripts/build_mobile.py --sync` 再重新安裝 |
